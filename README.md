# Slack Cipher

Chrome Manifest V3 擴充套件原型：在 extension-origin iframe 輸入明文、AES-256-GCM 加密後交給 Slack 原生輸入框送出，讀取時在本機解密並顯示文字。無伺服器、無第三方套件、無需編譯。

## 安裝與使用

1. 開啟 `chrome://extensions`，啟用「開發人員模式」。
2. 按「載入未封裝項目」，選擇本專案的 `extension` 目錄。
3. 點擴充套件圖示，按「產生金鑰」。
4. 第一把產生或匯入的金鑰會自動成為預設金鑰。之後可選擇其他金鑰，按「將選定金鑰設為預設」。所有對話共用此送出金鑰，不需設定頻道。
5. 重新整理 Slack；原輸入區應被綠框安全輸入區取代。Enter 送出、Shift+Enter 換行。IME 選字 Enter 不送出。
6. 其他收件者安裝套件，透過 Slack 以外的可信管道取得並匯入同一單行金鑰；收件者須持有對應金鑰才能閱讀。所有標準頻道、私訊與群組私訊均可顯示覆蓋輸入框；未設定金鑰時會阻止加密送出，仍可手動切換明文。

請先在自己的私訊測試。在設定頁隱藏覆蓋輸入框即可回復原生輸入框。安裝前請先處理原生草稿：套件不會覆寫它，也不會將它自動加密送出。若送出結果不明，先確認 Slack 是否收到，勿直接重送。

## 金鑰管理與輸入框開關

- 設定頁可產生、貼上匯入、複製匯出、選擇預設及移除金鑰。移除前會要求確認；未備份的金鑰無法復原，也無法再解密對應的歷史訊息。重新貼上原金鑰可恢復讀取。
- 匯出直接將 64 碼 hex 金鑰複製到剪貼簿；匯入時貼上該行文字並按「匯入金鑰」，不使用檔案。識別碼由金鑰原始 32 bytes 的 MD5 轉成 Base62 後取低位 12 碼（大小寫英文字母與數字，字母表為 A–Z、a–z、0–9），同一把金鑰重複匯入不會新增副本。
- 移除預設金鑰後不會自動改用其他金鑰，即使只剩一把也一樣；請自行選擇預設金鑰。加密啟用時會阻止沒有預設金鑰的送出操作。
- 設定頁的「顯示覆蓋輸入框」控制所有標準對話與對話串是否顯示自訂輸入框；隱藏時恢復原生輸入框。讀取既有密文不受影響。
- 覆蓋輸入框內的「加密送出」控制該輸入框的送出模式。取消勾選會以明文送出，覆蓋框與草稿都保留。主對話與對話串獨立切換，新輸入框預設開啟加密；按鈕會顯示「加密並送出」或「明文送出」。
- 隱藏覆蓋輸入框不會把草稿複製到原生輸入框，草稿可從下方備份區復原。若原生輸入框已有草稿，重新顯示覆蓋輸入框後仍會阻止覆寫。

未送出明文草稿備份於擴充套件的 `chrome.storage.session`，不寫入磁碟或 Slack。切換頻道、輸入框重建或重新整理後，可在設定頁的「未送出草稿」複製復原；關閉瀏覽器、停用或重新載入套件會清除。送出成功後移除對應備份。

更新或重新載入擴充套件後，也需要重新整理已開啟的 Slack 分頁。偵測到擴充套件執行環境失效時，舊腳本會停止掃描及 API 呼叫，保留原本顯示的草稿並提示重新整理。覆蓋輸入框原本顯示時維持阻擋送出，請先複製未送出文字，再按「重新整理 Slack」。

## 對話串

主對話與側欄對話串各有獨立的安全輸入框。對話串的頻道與識別碼從其訊息連結辨識，送出時只操作該輸入框的原生送出按鈕，不會使用主頻道的送出按鈕。切換對話串或輸入框重建後，舊送出請求會被拒絕；未送出草稿的備份會標示對話串識別碼。

對話串訊息依所屬頻道解密，側欄顯示其他頻道的對話串也不會沿用主畫面的頻道。無法辨識對話串時保留覆蓋層並阻止送出。隱藏覆蓋輸入框時，主對話與對話串的原生輸入框都會恢復。

## 格式與安全邊界

`<Extension A 標記><12 碼 Extension A key ID><漢字編碼 envelope><Extension A 補位碼>`

訊息以隨機 CJK Extension A 字元（U+3400–U+4DBF）開頭，降低一般中文訊息觸發解密的機率。key ID 和補位碼也使用隨機 Extension A 字元，分別取餘數 62 和 14 還原。舊版 `⚿:` 格式仍可解密；取餘數可還原 ID，因此此方法不提供金鑰使用的不可連結性。

密文以每字元 14 bits 的漢字編碼（U+4E00–U+8DFF）傳送，最後一碼以 Extension A 字元取餘數表示補位 bit 數（0–13），因此密文內容全部由漢字組成。這僅縮短字元數；漢字通常較寬，UTF-8 傳輸位元組數也不會減少。256-bit 金鑰以單行 64 碼 hex 交換，不包含識別碼或其他欄位。

- 金鑰使用 CSPRNG 產生；ID 為原始金鑰 bytes 的 MD5 衍生之 12 碼 Base62，只用於識別，不用於加密或密碼衍生。同一 ID 不允許匯入不同金鑰。
- Envelope 是 1-byte 格式版本、12-byte 隨機 nonce、AES-GCM ciphertext 與 128-bit tag。版本與 key ID 分開，版本不是 key 代號。
- AAD 綁定格式版本、key ID、workspace/channel。跨頻道貼上將無法解密；同頻道重播與冒用發送者尚未防護，也未綁定 thread。
- 金鑰為隨機 256-bit，存於 `chrome.storage.local`，限制為 trusted extension contexts；content script 只能請求背景程序加解密。沒有雲端同步、主密碼、前向保密或成員撤銷協定。
- 加密模式下，明文不進入原生輸入框，但解密結果會放回 Slack DOM，Slack 頁面程式可能讀取。這不是對惡意 Slack 頁面的完整端對端隔離保證。
- 所有對話共用預設送出 key；持有該 key 的人若取得其他對話的密文及對話 ID，也能解密。這不提供各對話間的金鑰隔離。讀取仍依每則訊息的 key ID 選用金鑰，切換預設 key 不影響舊訊息。
- 匯出的單行金鑰及剪貼簿含原始秘密；遺失 key 無法恢復歷史訊息。換 key 請建立新 ID 並保留舊 key。
- Slack 仍可見參與者、時間、頻道與密文長度。搜尋、通知預覽、原生複製、引用與手機／桌面版不會自動解密。
- 第一版僅支援標準頻道／私訊頁面的純文字新訊息與 thread 輸入框。顯示覆蓋輸入框時隱藏原生輸入工具；附件、編輯、排程、Canvas、跨頻道分享及其他非標準送出入口不保證受保護。請不要透過這些入口傳送秘密。
- Slack DOM 是非公開整合介面，更新後可能不相容。保留原始密文 DOM，在相鄰文字區呈現解密結果；節點回收、路由切換、密文更新時清除舊結果。使用 `textContent`，不執行明文 HTML。
- 送出成功的判準是 Slack 清空原生輸入框，並非伺服器送達回條。加密失敗不會退回送明文，也不會自動重試。

## 驗證

使用 Node.js 22.22.2+、24.15+ 或 26+，先執行 `npm ci`，再執行 `npm test`。jsdom 僅供測試，不會打包進擴充套件。測試涵蓋加密驗證、金鑰生命週期、背景訊息授權、並行寫入，以及模擬 Slack DOM 的覆蓋、密文送出、路由切換與節點回收。語法檢查：`node --check extension/content.js` 等。

目前自動測試與語法檢查通過；真實 Slack 的擴充套件載入及送出測試尚未完成，仍須依下列清單驗收 DOM 相容性。

實機驗收清單：雙裝置相同 key 可解密、錯 key／修改密文拒絕解密、Enter／按鈕只送密文、IME／Shift+Enter 不送出、thread、切換頻道、捲動歷史與重新整理、缺 key、離線或送出失敗保留草稿、原生草稿不覆寫、金鑰匯出匯入、預設金鑰切換、所有對話自動啟用、缺 key 仍覆蓋原輸入框、停用套件後回復原生輸入區。
